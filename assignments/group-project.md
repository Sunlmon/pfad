# Group project: build something together

**Weight:** 40% of the course grade

**Final deadline:** Sunday 6 December 2026, 23:59 Hong Kong time

Make an original app, game, installation or other interactive project with your
team. Build something a person can use or experience: explain who it is for,
what they do, and how your project responds. Include multimedia appropriate to
your idea. Agree the scope with your instructor and choose a first interaction
that you can test early. You may use AI to help build; your finished project does
not have to contain AI.

## Begin this week

Create one shared GitHub repository and give your teammates access. Submit its
**repository URL on Canvas** as soon as it exists; an initial README is enough to
register the project. Keep developing the same repository after submitting it.
Make sure the instructor can access the repository. The final deadline above is
for the finished work; check Canvas for the assignment and its actual settings.

## What the repository should show

- The working project and source code, with a clear description of the idea and
  its intended user or audience.
- A `README.md` explaining prerequisites, setup, how to run or access the result,
  chosen platforms and any limitations. A link to a live deployment or a
  downloadable build helps when appropriate.
- Visible participation by the team: meaningful contributions, small commits
  and a record of weekly progress. Show shared planning, task ownership,
  review/test evidence and how the next plan changes as you learn. GitHub
  Projects and Issues are recommended; an equivalent accessible shared record
  is valid. Link your board and progress notes from the README, and ensure the
  instructor can access them. See the [Week 8 teamwork guide](../week08/teamwork.md).
- Credits for code, assets, data and tools, including how AI tools were used.
  Use original or appropriately licensed material.
- Instructions for configuring any required secrets. Never commit or submit
  passwords, API tokens, signing keys or private personal data.

Choose the tools and delivery targets that suit your project. A website,
downloadable application, game or installation can all be appropriate; app
stores and a particular framework are not mandatory. Test the actual experience
with another person, not just the build command.

## How it is marked

The group project is **40% of the course grade**. Its own mark is divided into:

| Criterion | Share | What we look for |
| --- | ---: | --- |
| Creative idea | 25% | Novelty and value of the idea. |
| Code | 50% | The project works, meets the requirements and handles complexity well. |
| Execution | 25% | Small, steady increments and documented weekly progress, evidenced by shared planning, team contributions, review and adaptation. |

The execution criterion assesses how the team develops the project over time.
Use brief weekly goals, completed work, feedback, blockers and next steps to
explain the evidence. Raw commit/card counts, formal Scrum titles and ceremony
attendance are not the criteria. This is ongoing documentation linked from the
same repository; it does not introduce an additional Canvas upload.
