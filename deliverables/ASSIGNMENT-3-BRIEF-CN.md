# Assignment 3：互动体验

**个人项目｜占总评 15%｜满分 15 分**  
**截止时间：2026 年 11 月 1 日（星期日）23:59，香港时间**

## 一句话要求

制作一个可以让人实际使用的小型互动体验。用户要能够主动操作，程序要产生有意义的回应，并通过清楚的反馈让用户理解发生了什么、接下来可以做什么。

核心结构是：

```text
用户输入 / 操作 → 程序回应 → 清楚反馈 → 用户决定下一步
```

作品可以是网站、互动艺术、分支问卷、小游戏、实用工具或命令行体验。重点不是功能数量，而是完成一个范围合理、可解释、可测试的互动。

## 必须做到的互动内容

1. **有明确的用户操作**
   - 可以是点击、按键、下拉选择、输入文字、滑杆、拖曳或其他适合概念的输入。

2. **操作必须造成有意义的变化**
   - 用户输入必须改变程序实际做的事情，而不能只是页面装饰变化。

3. **有清楚的反馈**
   - 用户要能知道操作是否生效、发生了什么，以及下一步怎样继续。
   - 如适用，必须让用户知道怎样重置、返回或停止。

4. **处理一种常见问题或中断**
   - 例如：空白输入、重复点击、资料缺失、用户拒绝麦克风权限、服务不可用等。

5. **至少找一位其他人试玩**
   - 在你解释玩法之前，请对方自己尝试。
   - 观察对方做了什么、在哪里犹豫、是否理解程序回应。
   - 根据观察改善至少一处；如果决定不改，也要说明原因。
   - 在 `PROCESS.md` 记录观察和你的决定；不需要写试玩者姓名。

## 可以使用什么

你可以使用图片、动画、声音或 AI 模型，但都不是必须的。

不需要付费账户、高性能 GPU 或麦克风。若使用外部服务或本地模型，必须说明安装或运行方式，并提供示例或演示，让老师在该依赖无法使用时仍能理解作品的互动。

你可以：

- 从课程示例开始；
- 扩展 Assignment 2 的数据作品；
- 制作全新的互动作品。

但是，如果使用课程示例或 Assignment 2，必须说明你新增了什么、为什么新增。静态图片、没有用户控制的视频，或没有实质改动的教程示例，都不符合本作业的互动要求。

## 提交内容

在 Canvas 提交一个**公开 GitHub 仓库的网址**。仓库必须在你自己的 GitHub 账号下，并使用项目名称，而不是 `assignment3`。

仓库应包含以下内容：

### 1. 可运行的源代码与必要素材

- 包含作品运行所需的代码和素材。
- 清楚记录依赖。
- 如果使用 Python，提供准确的 `uv run` 命令，以及 dependency metadata 或 requirements 文件。
- 如果是网页项目，说明怎样启动本地服务器和打开页面。

### 2. `README.md`

README 必须说明：

- 作品概念；
- 目标用户；
- 主要互动是什么；
- 如何运行；
- 已知限制；
- 一张截图；
- 如有，可加入线上链接；
- 如作品包含声音、动画或本地应用，短录屏会有帮助。

### 3. `PROCESS.md`

PROCESS 必须说明：

- 最初的想法；
- 一项你做出的设计或代码修改；
- 用户试玩时观察到什么；
- 你根据试玩做了什么决定；
- 使用了哪些 AI 工具、分别用于什么；
- 一条你保留的 AI 建议，以及一条你修改或拒绝的建议，并说明原因。

如果没有使用 AI，也要如实说明。

### 4. Credits 与开发历史

- 标注借用的代码、数据、图片、音频和课程示例。
- 在项目开发过程中持续 commit，让 Git 历史显示你的设计决定与修改过程。
- 不要上传 API key、个人资料或其他人的录音。
- 所有公开素材必须有分享权限。
- 用无痕模式或登出 GitHub 后检查仓库链接是否仍可打开。

## 一个适合本课程的最小互动公式

```text
一个明确动作 + 一个可感知回应 + 一个清楚反馈 + 一个重置或错误处理
```

例子：用户点击一根鸟类羽毛 → 羽毛被选中、播放声音、显示物种资讯 → 用户可按 Reset 回到初始状态；若声音无法播放，则显示文字提示，但视觉互动仍可继续。
